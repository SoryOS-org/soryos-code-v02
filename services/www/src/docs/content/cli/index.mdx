Run the CLI in a project to open the full-screen terminal interface:

```bash
lutungcode
```

Pass a directory to work in a different project:

```bash
lutungcode ~/code/my-project
```

Suggested terminals:

- [Ghostty](https://ghostty.org)
- [WezTerm](https://wezterm.org)
- [Alacritty](https://alacritty.org)
- [Kitty](https://sw.kovidgoyal.net/kitty/)

Truecolor support gives themes their most accurate colors; terminals without it use an approximation of the available
palette.

## Automation

Use `lutungcode run` to submit a prompt without opening the interactive interface. It is designed for scripts, CI jobs, and
other workflows that need model output directly in the terminal.

```bash
lutungcode run "Explain this repository"
```

## Mini

Use `lutungcode mini` to start LutungCode's minimal interactive interface instead of the full-screen TUI.

```bash
lutungcode mini
```

Run `lutungcode mini --help` to see its session, model, agent, prompt, and replay options.

## Background service

By default, LutungCode discovers or starts one shared background server for your user account. Every local LutungCode client
connects to that server, which owns sessions, configuration, integrations, permissions, and tool execution.

Use `--standalone` to run with a private server, or `--server` to connect to a specific server URL:

```bash
lutungcode --standalone
lutungcode --server http://localhost:4096
```

To make private servers the default for CLI commands instead of starting the shared service, disable it:

```bash
lutungcode service set disabled true
lutungcode
```

This stops the running background service. `--server` still connects to an explicitly selected server; `lutungcode service start`
can still start the shared service explicitly. To return to automatic service use, run `lutungcode service unset disabled`.
Pairing requires the shared service and is unavailable while it is disabled.

See [Troubleshooting](/troubleshooting) for shared service diagnostics and the [API reference](/api) for server endpoints.

## Paths

Print a specific local path for use with other tools:

```bash
lutungcode debug paths db
sqlite3 "$(lutungcode debug paths db)"
```

The optional selector accepts `db`, `home`, `data`, `config`, `cache`, `state`, `tmp`, `bin`, `log`, or `repos` and prints
only the path and a newline. The database path respects the release channel and `LUTUNGCODE_DB`; relative database overrides
resolve under the data directory, and `:memory:` is printed as-is. This command does not start a server or open the database.

Omit the selector to show all paths with labels:

```bash
lutungcode debug paths
```

## Uninstall

Preview the files and installation that will be removed:

```bash
lutungcode uninstall --dry-run
```

Run `lutungcode uninstall` to confirm removal. LutungCode stops registered background services and persistent terminals before
removing the global cache directory, which is shared by LutungCode versions and channels. Session data, configuration, and
state are never removed.

- `--force` (`-f`) skips confirmation; use it for noninteractive removal.
- Package-manager installations use the detected package manager. Curl installations print the final command to remove
  the executable manually.
